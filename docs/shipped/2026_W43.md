## S3 y CloudFront con URLs firmadas

Intención: sustituir el adaptador S3 pendiente por guardado/borrado real y lectura privada
CloudFront, siguiendo el patrón de Admin y la confirmación de firmas obligatorias para Academy.

Rama/PR: cambios locales; sin publicación ni despliegue.

Cambios: AWS SDK v3 para PutObject/DeleteObject, sin ACL pública; firma RSA 2048/SHA256 con TTL
configurable de 300 segundos por defecto. El puerto separa URL canónica persistible de URL de
lectura. Portadas, avatares y recursos resuelven sus claves al responder, después de autorizar;
los DTOs no exponen claves y la lección bloqueada no firma recursos. La API envía no-store.
La compensación de recursos solo elimina bytes si falla la persistencia, no si falla una firma
posterior al guardado. Los errores operativos usan 503 STORAGE_UNAVAILABLE sin detalles sensibles.

Configuración: región/bucket, base CDN HTTPS, par opcional AWS o default credential chain/IAM,
session token, ID de clave pública y una fuente del PEM (inline o archivo), validada al inicio.
`.env.example`, el `.env` local ignorado y las guías describen las variables admitidas. Se
conservaron los valores existentes; el entorno local sigue con driver local y datos AWS vacíos.

Verificación ejecutada: `pnpm prisma:generate`, `pnpm lint`, `pnpm typecheck`,
`pnpm typecheck:tests`, `pnpm boundaries`, `pnpm test` (110 suites, 778 pruebas), `pnpm build`,
`pnpm docs:citations`, Prettier sobre `docs/**/*.md` y `git diff --check`, sin fallos.
Los tests usan S3 simulado y RSA efímera, verifican firmas SHA256 contra la clave pública,
caducidad/renovación, claves inseguras, configuración y persistencia de URLs estables.

Pendientes: completar credenciales/rol, región, bucket, dominio e ID/PEM reales; exigir firmas
en los comportamientos CloudFront con grupo confiable y mantener S3 privado con OAC. Migrar
bytes/filas legacy antes de activar S3 y verificar subida/lectura/borrado, CORS y 403 sin firma,
alterada o vencida. Confirmar renovación de enlaces desde el frontend. No se ejecutaron pruebas
contra AWS, integraciones PostgreSQL ni migraciones sobre la base habitual.
