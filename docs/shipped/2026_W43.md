# Deliveries · 2026 W43

## S3 and CloudFront signed URLs

Intent: replace the pending S3 adapter with real storage/deletion and private CloudFront reads,
following Admin's pattern and the confirmed signed-access requirement for Academy.

Branch/PR: local changes; no publication or deployment.

Changes: AWS SDK v3 PutObject/DeleteObject without public ACLs; RSA 2048/SHA256 signing with a
configurable TTL, defaulting to 300 seconds. The port separates persistable canonical URLs from
read URLs. Covers, avatars, and resources resolve their keys after authorization; DTOs do not
expose keys, and locked lessons do not sign resources. API responses use no-store. Resource
compensation only deletes bytes after persistence fails, not after a later signing failure.
Operational failures return 503 STORAGE_UNAVAILABLE without sensitive details.

Configuration at this stage: region/bucket, HTTPS CDN base, optional AWS key pair or default
credential chain/IAM, session token, public-key ID, and one PEM source (inline or file), validated
at startup. The then-existing `.env.example`, ignored local `.env`, and guides listed supported
variables. Existing values were preserved; local storage remained active with empty AWS settings.
The local configuration files were removed during the preparation entry below.

Verification: `pnpm prisma:generate`, `pnpm lint`, `pnpm typecheck`, `pnpm typecheck:tests`,
`pnpm boundaries`, `pnpm test` (110 suites, 778 tests), `pnpm build`, `pnpm docs:citations`,
documentation Prettier, and `git diff --check` passed. Tests used mocked S3 and ephemeral RSA,
checking SHA256 signatures against the public key, expiry/renewal, unsafe keys, configuration,
and stable persisted URLs.

Remaining work at this stage: supply actual role/credentials, region, bucket, domain, key ID/PEM;
require signatures in CloudFront behaviors using a trusted key group and private S3 with OAC.
Migrate legacy bytes/rows before enabling S3; verify upload/read/delete, CORS, rejection of missing,
tampered, and expired signatures, and frontend renewal. No AWS checks, PostgreSQL integration,
or migrations on the normal database were run in this delivery.
